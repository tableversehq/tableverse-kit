The generated `tableverse.config.ts` already describes both packages:

```ts
import { defineConfig } from "@tableverse-kit/config";
import { game } from "./engine/src/game.ts";

export default defineConfig({
  game,
  publish: {
    engine: "./engine",
    frontend: "./client",
  },
});
```

Paths are relative to the config file. Keep `package-lock.json` beside `tableverse.config.ts`; Tableverse installs the complete npm workspace from this project root.

## Upload your game

From the project root:

<Steps>
  <Step title="Check the project">

```bash
npm run typecheck
npx tvk validate
```

  </Step>
  <Step title="Sign in">

```bash
npx tvk login
```

    The CLI opens your browser to authenticate.
  </Step>
  <Step title="Upload">

```bash
npx tvk upload
```

    On the first upload, choose an existing game or create one. The CLI saves that choice in `.tableverse/game.json`.
  </Step>
  <Step title="Follow the build">
    The CLI prints a deployment dashboard URL and opens it when possible. Tableverse builds your engine and frontend from the uploaded workspace.
  </Step>
</Steps>

<Warning>
  Check the game name and ID printed before every upload. A copied project may still contain a link to the original game.
</Warning>

Local `.env` files stay on your machine. Configure deployment secrets in Tableverse.

For CI, set `TABLEVERSE_GAME_ID` to select the game without an interactive prompt.
